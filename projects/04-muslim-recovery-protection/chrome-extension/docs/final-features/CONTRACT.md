## Module ownership and integration API

- Security worker: `createFeatureController(api)` in background/feature-controller.js. `handle(message)` returns reply for feature messages or undefined for legacy protection messages. `authorize(message)` guards private operations. `filterStatus(reply)` strips private settings when locked. Root/Protection integrates it before legacy validate/handle. Public preferences are non-sensitive: language,religion,faith,theme,prayer config. Private vault: covenant,notes,customSteps,favorites,reviews.
- Public `GET_PUBLIC_PROFILE` -> `{ok:true,profile:{language,religion,faith,theme,prayer},security:{enabled,locked}}`. `SAVE_PUBLIC_PROFILE` with `{profile}` partial validated updates; gated except onboarding initialization, protection unaffected.
- Vault `GET_PRIVATE_DATA` -> `{ok:true,data}`; `SAVE_PRIVATE_DATA` `{data}` validated replacement; password protection enforced by worker, session unlock held in worker memory, fails closed across restart. `SET_PASSWORD` `{password}` returns one-time recoveryCode. `UNLOCK` `{password}`; `LOCK_ACCESS`; `RECOVER_PASSWORD` `{recoveryCode,password}`. Security changes never alter commitment or core records.
- Security feature operations return `{ok:false,error:{code,params:{}}}` without input text. UI must handle locked/unavailable state and retain drafts. Blocked pages may only request public profile. Help may explicitly load/save private custom ideas, favorites and unsuitable entries on user gesture with unlocked private session; session-only help remains available when locked. Explicit review persistence from recovery requires an unlocked private session, without preventing completing the help flow. Sender-specific worker capability checks enforce these boundaries.
- Existing `GET_STATUS` remains protection status, includes `security` metadata; locked replies redact `settings/config` and personal schedules. Legacy protection editing/export/reset/early exit authorization must be enforced in worker, not just UI.
- Protection owns `SAVE_SCHEDULES` `{schedules}`, `GET_SCHEDULES`, `REQUEST_EARLY_EXIT`, `CANCEL_EARLY_EXIT`, `CONFIRM_EARLY_EXIT` `{password}`, and start session accepts `{minutes,exitDelay}`; compatibility old 60/90/120 start supported. Coordinates with security verifier for exit password. Status supplies current deadline, scheduled state and exit request only as appropriate.
- Popup current-site block uses explicit user gesture + optional activeTab permission, never broad tabs/history collection. Protection owns `BLOCK_CURRENT_SITE` `{domain}` and validates current-tab-derived domain normally. No content script.
- Prayer owns pure calculation and worker `createPrayerController(api)` / `handle(message)` for prayer operations, plus lifecycle reconciliation; root integrates listeners and build permissions after review. Main preferences must stay consistent through SAVE_PUBLIC_PROFILE.
- UI shared `common.js`: `initPage()` resolves saved language/theme; synchronous `t()` legacy locales and new feature dictionaries; `send()` extension messaging. Added pages flat under src/ui and permitted extension senders only. No inline scripts/styles; CSP retained.
